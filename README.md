# Суварстроит — кейс рекламной кампании

Страница на HTML, CSS и JavaScript по [актуальному макету Figma](https://www.figma.com/design/gfvyQZPlrQKhItfbCgO4AP/Untitled?node-id=15-408). Для телефона используется фрейм `15:828`. React и Tailwind не используются. GSAP, шрифты и изображения находятся локально.

## Открыть страницу

Можно открыть `index.html` прямо в браузере. Для разработки:

```sh
npm install
npm run dev
```

`npm run build` собирает самостоятельную папку `dist`. Её содержимое можно загрузить на любой статический хостинг. Сборка и подключение к интернету не нужны для просмотра готовой страницы.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает и публикует страницу после отправки изменений в `main`. Он устанавливает зависимости через `npm ci`, оптимизирует изображения и собирает HTML, CSS, JavaScript и локальные ресурсы. Перед публикацией `npm run check` проверяет синтаксис JavaScript, наличие ресурсов и совместимость путей с адресом репозитория на Pages. Папка `dist` пересоздаётся при каждой сборке; файл `.nojekyll` отключает обработку Jekyll.

## Оптимизация изображений

Кладите исходные JPEG и PNG в `assets/` или её подпапки, кроме `assets/optimized/`. Sharp установлен как зависимость для разработки и запускается только в Node.js при подготовке сборки. В браузер он не попадает.

Команда `npm run optimize:images` создаёт WebP в `assets/optimized/`: качество 80, максимальная ширина 1920 пикселей. Маленькие изображения не увеличиваются; пропорции и прозрачность сохраняются. Оригиналы не изменяются. Подпапки сохраняются, а к имени добавляется `.webp`: например, `assets/photo.jpg` превращается в `assets/optimized/photo.jpg.webp`. Это исключает совпадение имён у `photo.jpg` и `photo.png`.

Для увеличенных изображений веток в `assets/Upscaled/` действует отдельный режим: WebP без потерь, без уменьшения размеров, с сохранением прозрачности и цветов каждого пикселя. Готовые файлы появляются в `assets/optimized/Upscaled/`. Соответствия старых ассетов и новых файлов указаны в `tools/image-overrides.json`; суффикс ` 1` в некоторых именах сохранён. Для `fa6f6.png` выбрана версия 2172 × 1629 пикселей. При сборке все ссылки на заменяемые ассеты, включая повторяющиеся слои, автоматически получают увеличенные версии. Исходные PNG и расположение слоёв не меняются.

Новые увеличенные ветки кладите в `assets/Upscaled/`, затем добавляйте соответствие в `tools/image-overrides.json`. Если указанный исходник или его замена отсутствуют, сборка останавливается с ошибкой. Все изображения в `Upscaled` сжимаются без потерь; файлы, не используемые на странице, остаются подготовленными для будущих слоёв.

Левый фрагмент ветки `15:806` в главе IV использует полный исходник `a8189.png` с отдельной маской в координатах макета. При замене `assets/Upscaled/a8189.png` этот фрагмент тоже обновляется автоматически.

Обновлённые таблицы главы III находятся в `assets/tables/`. Они также сжимаются в WebP без потерь и без уменьшения размеров, чтобы сохранить мелкий текст и прозрачность. Готовые файлы появляются в `assets/optimized/tables/`. Старые оригиналы сохранены; их прежние адреса при сборке заменяются согласно `tools/image-overrides.json`. Перед основной информацией главы III добавлен дисклеймер о числовых данных в обеих версиях страницы; он сохраняется при повторном преобразовании дизайна.

Для оптимизации и production build достаточно одной команды:

```sh
npm run build
```

Перед сборкой npm автоматически запускает оптимизацию через `prebuild`. В копиях HTML, CSS и JavaScript внутри `dist` ссылки заменяются на WebP, включая изображения для анимации фонарей. Исходные страницы сохраняют ссылки на оригиналы, поэтому разработка и открытие исходного `index.html` работают как раньше. В `dist/assets/optimized/` попадают готовые WebP; исходные JPEG и PNG в сборку не копируются. SVG, шрифты и прочие ресурсы копируются без изменений.

Папка `assets/optimized/` создаётся заново при каждом запуске и исключена из Git. Не храните в ней исходники и не редактируйте её содержимое вручную. Для проверки готовой сборки используйте `npm run check`, для просмотра — `npm run preview`.

Публикация выполняется через GitHub CLI без браузера. CLI должен быть авторизован; для токена нужны права записи в репозиторий, изменения workflows и настройки Pages. Токен вводится локально через `gh auth login --with-token` и не сохраняется в файлах проекта.

После создания репозитория и отправки исходников включите Pages через API (замените `OWNER/REPO` на выбранный репозиторий):

```powershell
gh api --method POST repos/OWNER/REPO/pages -f build_type=workflow
gh workflow run pages.yml --repo OWNER/REPO --ref main
gh run list --repo OWNER/REPO --workflow pages.yml
```

Для репозитория с уже включённым Pages используйте `--method PUT` вместо `POST`. Успешную публикацию можно проверить командами `gh run view RUN_ID --repo OWNER/REPO` и `gh api repos/OWNER/REPO/pages --jq .html_url`.

## Что реализовано

- Отдельные композиции для компьютера и телефона, включая исходные маски и декоративные иллюстрации.
- Плавное горение всех шести фонарей на компьютере и трёх на телефоне: переход между исходным ярким состоянием и слабым состоянием, созданным через imagegen. Новое изображение накладывается только на стекло с мягкой маской; корпус, ветви, книги и город сохраняются. Циклы длятся 4,25–5,4 секунды; слабое состояние дополнительно затемнено. У всех фонарей есть мягкие тёплые ореолы, которые меняют прозрачность вместе с пламенем. Оранжевый световой эллипс Hero синхронизирован с верхним фонарём. Тёмная подложка Hero остаётся постоянной.
- Проявление текста через фактурную акварельную маску.
- На компьютерах в сцене после хиро фон плавно сдвигается вправо, стол — влево; диван и персонажи сохраняют положение. Движение связано с прокруткой и возвращается назад при прокрутке вверх. Мобильная сцена сохраняет прежнюю анимацию.
- Заметный тёплый след светлячков за курсором: до 24 частиц с ярким ядром диаметром 4,2–6,4 пикселя и мягким ореолом диаметром около 60 пикселей. Частицы плавно исчезают за 1,7–2,5 секунды после появления. На сенсорных устройствах эффект отключён.
- Переходы между главами, галерея, увеличение баннеров и таблиц, закрытие по Escape, возврат фокуса.
- Отключение эффектов кнопкой и поддержка системной настройки уменьшения движения.

В медиарамке главы IV размещены два видео: Су Анасы и Шурале. Видимый слайд показывает зацикленное превью без звука, если анимация включена. Кнопка просмотра открывает полноценный видеоплеер со звуком и стандартным полноэкранным просмотром. Переключение слайда и выход за пределы экрана останавливают превью; скрытая мобильная или компьютерная композиция не воспроизводит видео. При системном уменьшении движения и отключённой анимации автоматическое воспроизведение отключено, но просмотр по кнопке доступен.

После текста о размещении рекламы расположена горизонтальная лента с тремя роликами 6 × 3: Шурале, Зилант, Су Анасы. Видимые ролики автоматически воспроизводятся по кругу без звука и панелей управления. Несколько видимых роликов могут играть одновременно; скрытые, вышедшие за пределы экрана или перекрытые окном просмотра останавливаются. Отключение анимации и системное уменьшение движения также останавливают превью. Четвёртый материал в ленте — фотография билборда. Лента прокручивается свайпом, полосой прокрутки и клавиатурой; фотография открывается в увеличенном виде. Постоянно видимая полоса прокрутки находится под лентой с отступом 12 пикселей от её нижней границы и синхронизируется со свайпом и клавиатурой. Под лентой размещён заголовок «Наши персонажи на билбордах:» и прежние фотографии в декоративных рамках. Материалы находятся в `assets/media/`, изображения и постеры автоматически оптимизируются при сборке. MP4 сохранены без перекодирования. Подзаголовки глав II и III убраны; названия глав сохранены.

Ветка `15:795` над главой IV опущена до `12583px` и обрезана до ширины `1094px` согласно Figma. Внутри обрезки используется полный увеличенный `45b01 1.png`, оптимизированный без потерь, чтобы прикрыть стык без снижения качества.

Разметка медиа хранится в `tools/campaign-media.mjs`. Композиция главы IV для компьютера сохранена в `tools/reference/chapter-four-current.txt` и применяется к основному экспорту через `node tools/update-chapter-four-reference.mjs`, сохраняя исправленные хиро и фонари. Скрипт `tools/convert-design.mjs` использует точные координаты обновлённого макета, подключает медиа к обеим композициям и удаляет выбранные подзаголовки. Изменения сохраняются при повторном преобразовании экспорта Figma. Большая цветочная рамка `abee1.png` при сборке заменяется увеличенной версией `Upscaled/fa6f6.png`, которая сжимается в WebP без потерь.

## Файлы

- `index.html` — содержимое и слои страницы.
- `design.css` — точные позиции и оформление слоёв из Figma.
- `styles.css` — адаптивность, навигация, просмотр изображений и эффекты.
- `script.js` — навигация, галерея, GSAP и масштабирование композиции.
- `effects.js` — акварельное проявление, переходы яркости фонарей и светлячки.
- `assets/` — оригинальные изображения, маски, шрифты и GSAP.
- `assets/lantern-hanging-dim.png`, `assets/lantern-books-dim.png`, `assets/lantern-city-dim.png` — три прозрачных слабых состояния из встроенного imagegen. Промпты сохранены в `assets/lantern-generation.json`.

В `tools/reference/desktop-current.txt` и `tools/reference/mobile-current.txt` сохранены экспорты актуального дизайна для повторного преобразования через `node tools/convert-design.mjs`. Экспорты старых фреймов сохранены отдельно в `desktop.txt` и `mobile.txt`. Они не исполняются на странице. Повторное преобразование перезаписывает `index.html`, `design.css` и `assets-manifest.json`; обычные правки страницы можно делать непосредственно в HTML/CSS/JS.

Четыре слоя сцены `34:1115` сохранены в `tools/reference/hero-scene-current.txt` и включены в актуальный экспорт. Для повторного применения этого фрагмента используется `node tools/update-scene-reference.mjs` перед преобразованием. Амплитуда параллакса в `script.js` составляет 96 пикселей вправо для фона и до 112 пикселей влево для стола в координатах макета; масштаб страницы автоматически уменьшает её на узких экранах компьютера. Стол `37:1118` перенесён без виньетки и сдвинут на 198 пикселей вправо относительно предыдущей версии. Движение стола останавливается, когда правый край слоя достигает правой границы области страницы в окне браузера. Если слой уже целиком помещается, движение влево отключается. При изменении ширины окна пересчитываются граница и диапазон прокрутки; фон продолжает двигаться независимо от остановки стола.
